# Resume Tailor

[English version](README.md)

Два независимых навыка для работы с фактическим карьерным опытом кандидата:

| Навык | Для чего нужен |
|---|---|
| `resume-tailor` | Адаптация резюме под вакансию, общая версия, правка раздела, проверка или запрошенное сопроводительное письмо. |
| `onboarding` | Создание или обновление мастер-профиля по предоставленным резюме, заметкам и карьерным фактам. |

Соответствие вакансии, достоверность фактов и качество документа оцениваются отдельно. Навык не рассчитывает общий ATS-балл или вероятность интервью, не требует повторять ключевые слова по квоте и не придумывает численные достижения. Язык, рынок, канал подачи и формат выбираются независимо. Кандидатом можете быть вы или другой человек, с чьими данными вы уполномочены работать.

Основной сценарий — инструкции и справочные материалы для совместимого агента. У плагина нет собственного сервера; ему не нужны API-ключ, платный сканер или средства экспорта для подготовки текста. При этом действуют правила обработки данных выбранного хоста.

В этой рабочей копии готовится **1.1.0**. Это не означает, что тег `v1.1.0`, архивы релиза или запись в официальном каталоге уже опубликованы. Установка с GitHub использует текущее содержимое удалённого репозитория. Для проверки подготовленных изменений до публикации используйте локальную копию.

## Выберите один способ установки

**Установка плагина** добавляет оба навыка вместе с метаданными хоста и записью маркетплейса. **Установка навыков** добавляет выбранные каталоги напрямую, без регистрации маркетплейса. Каждый навык работает отдельно и содержит собственную копию контракта профиля.

Для одного хоста и рабочего проекта выберите один способ. Одновременная установка через маркетплейс, Skills CLI или ручное копирование может создать дубликаты либо оставить активной старую копию.

### Skills CLI: установка в проект

Запускайте команды из рабочего проекта, где будете использовать навыки. Node.js/npm нужен установщику, а не самой работе с резюме.

```bash
# Просмотр доступных навыков без установки.
npx skills add olegvg/resume-tailor-plugin --list

# Оба навыка для двух хостов в текущем проекте.
npx skills add olegvg/resume-tailor-plugin --skill resume-tailor onboarding --agent codex claude-code

# Либо только onboarding.
npx skills add olegvg/resume-tailor-plugin --skill onboarding --agent codex claude-code
```

По умолчанию установка относится к проекту. Добавляйте `--global`, только если намеренно хотите установить навыки для пользователя во всех проектах. Для другого хоста выберите поддерживаемый идентификатор `--agent`. Для проверки подготовленной копии до публикации замените источник GitHub на `./resume-tailor-plugin`.

После публикации соответствующего тега можно закрепить версию:

```bash
# Этот пример работает только после публикации тега v1.1.0.
npx skills add https://github.com/olegvg/resume-tailor-plugin/tree/v1.1.0 --skill resume-tailor onboarding --agent codex claude-code
```

Закреплённый источник подходит для воспроизводимой установки. Для обновления навыков проекта доступными изменениями из источника:

```bash
npx skills update resume-tailor onboarding --project
```

Поддерживаемые хосты и поведение областей установки описаны в [документации Skills CLI](https://github.com/vercel-labs/skills).

### Плагин Codex

Если установленная версия CLI поддерживает `codex plugin`:

```bash
codex plugin marketplace add olegvg/resume-tailor-plugin
codex plugin add resume-tailor@resume-tailor
```

Для подготовленной локальной копии вместо удалённого источника используйте `codex plugin marketplace add ./resume-tailor-plugin`. Чтобы закрепить релиз после публикации тега, добавьте `--ref v1.1.0` к команде добавления удалённого маркетплейса.

Обновление настроенного маркетплейса и кешей установленных плагинов:

```bash
codex plugin marketplace upgrade resume-tailor
```

Если текущий сеанс ещё не обнаружил навыки, откройте новый после установки или обновления. Поддержка маркетплейсов может отличаться между интерфейсами Codex; сверяйтесь с `codex plugin --help` установленного CLI. См. [официальное руководство по упаковке плагинов](https://developers.openai.com/plugins/build/plugins).

### Плагин Claude Code

В примерах явно выбрана область проекта и для маркетплейса, и для плагина:

```bash
claude plugin marketplace add olegvg/resume-tailor-plugin --scope project
claude plugin install resume-tailor@resume-tailor --scope project
```

Обновите копию маркетплейса и установленный плагин, затем перезапустите Claude Code:

```bash
claude plugin marketplace update resume-tailor
claude plugin update resume-tailor@resume-tailor --scope project
```

Для проверки локальной копии без установки:

```bash
git clone https://github.com/olegvg/resume-tailor-plugin.git
claude --plugin-dir ./resume-tailor-plugin
```

В Claude Code навыки плагина вызываются как `/resume-tailor:onboarding` и `/resume-tailor:resume-tailor`, а установленные напрямую — `/onboarding` и `/resume-tailor`. В других хостах выберите навык в интерфейсе или попросите агента использовать его. См. [документацию плагинов Claude Code](https://code.claude.com/docs/en/plugins).

## Примеры использования

Пути ниже отсчитываются от **выбранного рабочего каталога кандидата**, а не от установленного плагина или его кеша. Передайте свои файлы или вставьте данные в чат. Мастер-профиль хранит карьерные факты; это не готовое резюме.

### Новый или анонимный профиль

```text
Используй onboarding. Создай мастер-профиль по sources/resume.md и заметкам ниже
в этом рабочем каталоге. Используй candidate-1 как метку файла; имя кандидата
неизвестно. Сохрани в resume/candidate-1/master-profile.md, оставь неизвестные
факты и ссылки на источники. Резюме и экспорт не нужны.
```

Для нового профиля путь по умолчанию — `resume/<candidate-label>/master-profile.md` в выбранном рабочем каталоге. Достаточно переданной метки или нейтральной метки, которая не конфликтует с существующими файлами. Имя, контакты, гражданство, дата рождения, фотография и численные достижения не являются обязательными условиями. Сначала навык извлекает имеющиеся факты, затем уточняет существенные пробелы. Если источники могут относиться к разным людям, это нужно выяснить до объединения записей.

### Обновление существующего профиля

```text
Используй onboarding. Обнови career-records/master.md по предоставленным
исправленным заметкам. Сохрани текущую схему, путь, остальные заметки и правки.
Укажи источник исправления; нерешённые противоречия оставь с оговорками.
```

Явно заданный путь имеет приоритет. Иначе можно использовать однозначно определённый существующий профиль. Своя схема и расположение не требуют миграции. Постоянные ограничения на раскрытие информации хранятся отдельно от решений для одной заявки или одного файла.

### Адаптация без сохранённого профиля

```text
Используй resume-tailor. Адаптируй переданное резюме кандидата под
jobs/platform-role.md. Запиши английское резюме в applications/platform/resume.md.
Работай прямо с предоставленными фактами, не создавай мастер-профиль.
Проверку размести отдельно от текста для работодателя.
```

Профиль необязателен. Можно вставить карьерные данные и вакансию в чат. Если URL вакансии недоступен, агент должен сообщить, какой информации не хватает, а не утверждать, что прочитал её.

### Адаптация из профиля или отдельная задача

```text
Используй resume-tailor с career-records/master.md и переданной вакансией.
Создай PDF в applications/role/resume.pdf. Убери языки только из этого PDF,
мастер-профиль не меняй. Используй разрешённые публичные названия работодателей
и описания проектов с учётом NDA.
```

Можно запросить общую версию без вакансии, правку одного раздела, проверку без переписывания или письмо без резюме. Запрос только для чата не создаёт файлов. Адаптация и экспорт не подразумевают создание или обновление профиля, отправку заявки либо изменение учётной записи на платформе.

Существующие правила включения разделов и варианты кандидата сохраняются. Поддерживаются `always`, `variant-specific`, `on-request` и `reference-only`. Последнее значение относится к внутренним данным: они не попадают ни в документ, ни в отчёт об исключениях. Указания для одного результата могут сузить допустимое утверждение или убрать раздел без изменения исходного карьерного профиля.

## Необязательный экспорт PDF и DOCX

Для текста в Markdown или чате средства экспорта не нужны. Для настоящего PDF подходит доступный инструмент HTML-to-PDF; один из вариантов — **WeasyPrint**, которому нужны Python, системные библиотеки и шрифты. Для настоящего DOCX можно использовать **python-docx** или средства хоста, создающие обычные абзацы документа. Для визуальной проверки нужен доступный рендерер документов.

Перед экспортом навык проверяет окружение. Конкретный пакетный менеджер или глобальная установка не требуются. Если инструмента нет, агент сообщает ограничение; установка зависимостей и изменение конфигурации требуют отдельного разрешения. Переименование HTML или PDF не превращает его в DOCX.

Экспорт не включает таблицы проверки и рабочие заметки. Перед сдачей файла нужно проверить извлечение текста, соответствие источникам и каждую отрисованную страницу. Локальные проверки не гарантируют поведение ATS или формы загрузки конкретного работодателя. См. [руководство по экспорту](skills/resume-tailor/references/document-export.md).

## Приватность и сопровождение

Данные кандидата и готовые файлы хранятся в выбранном приватном рабочем каталоге. Им не место в установленных ресурсах, кешах, публичных обсуждениях или архивах релиза. У плагина нет сервера и телеметрии; хост модели и подключённые вами инструменты обрабатывают данные по собственным правилам. Перед работой с чувствительными данными прочитайте [PRIVACY.md](PRIVACY.md).

Порядок сообщения об уязвимостях и поддерживаемый код описаны в [SECURITY.md](SECURITY.md).

Корневой `plugin.json` использует Agent Plugins schema 1.0.0; навыки обнаруживаются в двух каталогах внутри `skills/`. `.codex-plugin/plugin.json` служит слоем совместимости. `.claude-plugin/plugin.json` и оба индекса маркетплейсов указывают на один плагин. Наличие репозитория не означает размещение в официальном каталоге.

Для сопровождения: [AGENTS.md](AGENTS.md), [CHANGELOG.md](CHANGELOG.md) и [руководство по релизу](docs/releasing.md). Корневой `CLAUDE.md` — указатель для работы над репозиторием, а не контекст установленного плагина. Нативный валидатор Claude может предупреждать об этом при проверке рабочей копии.
